# 评估：rRNA 记录能否按序列本身核验归属（2026-11-13）

[← README](../../README.md)

**结论**：按标题把 "18S … ITS1, 5.8S, ITS2 … 28S" 记录同时放进 `18s`、`28s`、`its1-its2` 三列，在实测类群里是误导性的。这类记录里的 18S、28S 只是几十 bp 的引物端片段。区段坐标只能从序列本身得到：GenBank 注释在 86% 的这类记录里只有一个不分区段的 feature。用 Rfam 模型扫描序列可以可靠定位 5.8S，从而切出 ITS1、ITS2。下面是证据。脚本和中间数据目前不在仓库里，打算以 `g2t-verify` 的形式实现。

## 数据

- 类群：Enchytraeidae（txid6388），`g2t-download` 默认 markers 选择，10,773 条，2 分 23 秒下载完。
- `g2t` 流水线：10,689 条有基因类型，56 条被过滤，28 条未匹配。
- 标题含 ITS 或 5.8S 的记录 1,886 条，长度中位数 872 bp（229–1,178 bp）。

## 1. GenBank 注释里有没有区段坐标

| 注释方式 | 记录数 |
|---|---|
| 整条一个 `misc_RNA`，note 写 "contains 5.8S ribosomal RNA, internal transcribed spacer 2, and large subunit ribosomal RNA"，**没有区段坐标** | 1,620（86%） |
| 每个区段一个 feature，带坐标 | 265（14%） |
| 其他 | 1 |

所以只读注释（第 0 层）无法切分大多数 ITS 记录。

## 2. 序列扫描能否找回区段（第 1 层）

方法：Infernal `cmscan`（1.1.5）配 Rfam 的 5.8S（RF00002）、真核 SSU（RF01960）、真核 LSU（RF02543）协方差模型，取 E < 1e-5 的最佳命中。ITS1 = 18S 末端（或序列起点）到 5.8S 起点；ITS2 = 5.8S 终点到 28S 起点（或序列终点）。

用 265 条带坐标的记录当对照：

| 区段 | 注释条数 | 找到 | 边界与注释相差 |
|---|---|---|---|
| ITS1 | 263 | 262 | 中位数 0 bp；167 条 ≤ 5 bp，205 条 ≤ 20 bp |
| 5.8S | 265 | 264 | 起点：174 条正好重合，60 条差 1 bp；终点：注释普遍比模型长 19 bp（见下） |
| ITS2 | 264 | 264 | 中位数 19 bp（来自 5.8S 终点的定义差异） |
| 18S 片段 | 48 | 30 | 漏掉的全部 ≤ 47 bp |
| 28S 片段 | 51 | 39 | 漏掉的全部 ≤ 48 bp |

- **5.8S 终点的 19 bp 差别是定义不同，不是找错了。** 提交者把 5.8S 注释成 172–183 bp，Rfam 模型是 154 bp。命中覆盖了完整模型（262/264 条从第 1 位到第 154 位）。哪种定义对，未确证。
- 18S/28S 片段太短（< 50 bp）时 cmscan 找不到；能找到的片段本身也只有 18–78 bp。

速度：265 条用时 34 秒，1,886 条用时 4 分钟以内（8 线程）。

## 3. 全部 1,886 条 ITS 记录实际含多少 18S / 28S

| g2t 当前归类 | 记录数 | 18S 片段 | 28S 片段 | ITS1+5.8S+ITS2 占整条比例（中位数） |
|---|---|---|---|---|
| `18s,28s,its1-its2`（18-28s） | 689 | 中位数 32 bp，最长 52 | 中位数 37 bp，最长 67 | 93% |
| `18s,its1-its2` | 129 | 中位数 32 bp，最长 52 | 无 | 97% |
| `28s,its1-its2` | 667 | 无 | 中位数 37 bp，最长 58 | 92% |
| `its1-its2` | 401 | 45 条有，最长 41 | 59 条有，最长 50 | 100% |

- 没有一条记录含 ≥ 300 bp 的 18S 或 28S。
- 5.8S 在 1,883/1,886 条里定位到，全部在正链。

**含义**：这 1,485 条被同时放进 `18s` 或 `28s` 列的记录，对 18S/28S 系统发育没有用，反而会把只有几十 bp 引物端的序列混进比对。

## 4. 对改进方案的检验

| 设想 | 检验结果 |
|---|---|
| 按绝对 bp 多少归属 | 本类群 ITS 占 92–100%，结果正确；但对 "完整 ITS + 长段 28S D1–D3" 这类记录会归错，而且不解决“切出哪一段”的问题 |
| 按覆盖度归属（区段长度 ÷ 该区段典型全长） | 本类群 18S/28S 覆盖度 < 4%（67/1,831、67/3,401），ITS 完整，可作为主标签规则 |
| 只读注释坐标（第 0 层） | 86% 的 ITS 记录没有区段坐标，不够 |
| 序列扫描（第 1 层，Rfam + cmscan） | 5.8S 和 ITS1 起点定位与注释基本一致；可作为切分依据 |

## 5. 同一次检验顺带发现的问题

- **H3 拼写漏检**：28 条未匹配记录中 23 条标题写作 "histone3 (H3)"（无空格），feature 注释为 H3，g2t 词典没有这种写法。已补进 `gene_dict.yaml`，并加了测试（`tests/test_gene_dictionary.py::test_histone3_spelling_is_h3`；补之前失败，补之后通过）。
- 在 Haplotaxidae 示例（347 条，来自一篇论文）上，g2t 归类与 feature 注释 100% 一致。

## 6. 近全长 18S / 28S：哪种扫描方式可行

Enchytraeidae 中 60 条最长的 18S（1.75–1.83 kb）和 60 条最长的 28S（最长 3.4 kb），以 GenBank rRNA feature 坐标为对照：

| 方式 | 120 条用时（8 线程） | 18S | 28S |
|---|---|---|---|
| `cmscan`（完整协方差模型） | 38 分钟仍未跑完，中止 | — | — |
| `cmscan --rfam` | 40 分钟仍未跑完，中止 | — | — |
| `cmscan --hmmonly`（只用模型内的 profile HMM） | 61 秒 | 60/60，边界差均为 0 bp | 60/60，59 条 ≤ 5 bp |

完整协方差模型对近全长序列太慢；profile HMM 又快又准。代价是 < 50 bp 的引物端片段大多找不到（ITS 对照集：18S 片段 3/48，28S 片段 11/51），这些片段本来就不该算作 18S / 28S。

## 7. 12S、16S 与 18S、28S 的区分（Hesionidae）

模型：12S、16S 用 barrnap 0.9 的 mito.hmm；18S、5.8S、28S 用 Rfam 15.1 协方差模型内嵌的 profile HMM（RF01960、RF00002、RF02543）。用 pyhmmer（HMMER 的 Python 封装）运行，不需要另装程序。

**分类准确度（Enchytraeidae，标题与 feature 一致的记录各 150 条，用 barrnap 模型）**：

| 标题+注释 \ HMM 最佳命中 | 12S | 16S | 18S | 28S | 无命中 |
|---|---|---|---|---|---|
| 12S | 150 | 0 | 0 | 0 | 0 |
| 16S | 0 | 150 | 0 | 0 | 0 |
| 18S | 0 | 0 | 150 | 0 | 0 |
| 28S | 0 | 0 | 0 | 141 | 9 |

9 条无命中的都是 175–378 bp 的 28S 短片段。改用分段模型（见第 8 节）后，其中 3 条 171–177 bp 片段（GU453347、GU453352、GU453354）能找到。

> 更正：此前写“关掉加速过滤重扫可以找回 175 bp 片段”不对。那次能找回，是因为 E 值按当批序列总长计算，重扫的批次很小，E 值被放宽了。GU453353 对 28S 模型只有 4.3 bits（每 1 Mb 序列 E = 0.12），关掉过滤也不显著。现在 E 值固定按每 1 Mb 序列计算，结果不随批次大小变化。

**Hesionidae（2,250 条，g2t 冲突检查报告 0 个冲突）**：`g2t-verify` 扫描 904 条 rRNA 和未匹配记录。第一版用时 3 分 53 秒，加速后见第 8 节。

| 结果 | 条数 | 说明 |
|---|---|---|
| agree | 780 | |
| different | 5 | MG523356–60：标题和 feature 都写 "small subunit ribosomal RNA … mitochondrial"，g2t 归为 12S；序列 481–488 bp 全段匹配 16S。本地 BLAST：MG523359 与 16S 记录 OM403178 在 448 bp 上 100% 相同，MG523358 与 PQ771112 99%，MG523357 与 DQ442582 98%。同一凭证号另有 18S、28S 记录而没有 16S。**确认是 16S 被写成了 small subunit。** |
| partly | 14 | OQ703012、OQ703007：标题写 "small subunit rRNA and ITS"，序列几乎全是 18S（如 1,588 bp 中 18S 占 2–1576）；KP7455xx 等：只有 44–48 bp 的 18S 末端，其余是 ITS1 和 5.8S |
| unverifiable | 104 | 多数是 "ITS2 and large subunit rRNA, partial"（237 bp），没有 5.8S，无从定位 |
| no_hit | 1 | |

这 5 条错误只能靠序列发现：标题和 feature 写法一致，原来的冲突检查看不出来。

## 8. 加速（2026-11-13）

第一版对 Enchytraeidae 4,750 条记录要 10–12 分钟。逐步测量后找到的瓶颈和处理办法如下：

| 瓶颈（实测） | 处理 | 效果 |
|---|---|---|
| pyhmmer 的 `nhmmer` 每个模型只用一个线程。5 个模型里，28S 模型（3,401 个节点）占大部分时间，其余核心闲着 | 把“模型 × 序列块”拆成任务，用满全部核心 | 线程实测可扩展：4 线程约 4.6 倍 |
| 相同序列重复扫描：Hesionidae 904 条只有 605 种序列，Enchytraeidae 4,750 条只有 3,523 种 | 相同序列只扫描一次 | 计算量少 26–33% |
| 耗时在真正命中的序列上，与序列长度关系不大：一条 3,400 bp 的 28S 对完整 28S 模型约 0.3 CPU 秒，随机序列几乎不耗时 | 长模型（12S、16S、18S、28S）切成 300 个节点、互相重叠的分段模型，各段命中再按顺序拼回。分段模型用 pyhmmer Builder 从完整模型抽样 2,000 条序列重建，E 值经过校准，只在第一次使用时构建 | 总 CPU 时间从 525 秒降到 157 秒（含其他各项） |
| 单个分段在弱保守的末端可能对不上 | 区段末端离相邻区段或记录末端还有 ≥ 20 bp、模型那一侧也还有 ≥ 20 个节点时，只在这一小段上用完整模型补齐 | 涉及约 180 个末端，约 26 CPU 秒 |
| 每条记录都跑全部 5 个模型 | 先跑 g2t 所标类型的模型。强命中（≥ 0.3 bits/bp）已覆盖整条记录（最多剩 50 bp）就不再跑其他模型 | 只需第一轮的记录：Enchytraeidae 95%（4,494/4,750），Hesionidae 74%（671/904） |
| 结果缓存每次写盘都同步（fsync），WSL 下每次等数秒 | SQLite 用 WAL 模式并关闭同步；丢失缓存只意味着重扫 | 第二轮从 30 秒降到 1.4 秒 |
| 用 Biopython 读 GenBank 要 7.6 秒 | 整文件读入，按 `//` 切分 | 0.38 秒，输出与 Biopython 完全一致 |

**结果**：在 16 核、但被其他任务占满的机器上（负载约 37）实测，新旧版本在相同条件下运行。与第一版相比，有 28 条记录的结论不同，全部是新版找到了第一版漏掉的部分 5.8S（41–66 bp）或短 28S 片段：21 条由 unverifiable 变为 partly，4 条由 unverifiable 变为 agree，3 条由 no_hit 变为 agree。

| 数据 | 第一版 | 加速后，首次 | 加速后，重跑（有缓存） |
|---|---|---|---|
| Enchytraeidae 4,750 条 | 11 分 36 秒（CPU 938 秒） | 83 秒（CPU 162 秒） | 9 秒 |
| Hesionidae 904 条 | 3 分 53 秒 | 63 秒（CPU 84 秒） | 4 秒 |

**准确度**：与“每条记录跑全部完整模型”的结果逐条比较，全部 5,654 条记录如下。

- 结论：只有 4 条不同，而且都是改进。
  - Enchytraeidae 有 3 条 171–177 bp 的 28S 片段（标题写 28S）由 no_hit 变为 agree。
  - Hesionidae 的 LC788209：恢复了 77 bp 的 5.8S 部分片段，由 unverifiable 变为 agree。
- 区段坐标：相差 > 20 bp 的位点都是改进，没有一处丢失或变短。
  - 找到了 37–48 bp 的 18S/28S 引物端片段，ITS 边界因此更准。
  - Hesionidae 有 61 条 “ITS2 and 28S, partial” 记录找到 41 bp 的 28S 端。
  - OK044406 的 18S 从 1–953 延长到 1–1559：完整模型把命中拆成了两段，只取了其中一段。

## 实现：`g2t-verify`（已实现第一部分）

```bash
pip install pyhmmer        # 或 pip install -e ".[verify]"
g2t-verify -i gb/markers --g2t out -o verify
```

- 只扫描 rRNA、未匹配和有冲突的记录（`--all` 扫全部）。没有命中的记录再以 E ≤ 1e-3 扫一遍（Enchytraeidae 中找回 10 条 ITS 记录里的弱 5.8S）。
- 命中缓存在 `~/.cache/g2t/verify_hits.sqlite`，重跑只扫描新的序列（`--no-cache` 关闭）。`--all-models` 对每条记录跑全部模型。
- 输出 `verify.csv`（每条记录：g2t 类型、序列支持的类型、结论、各区段坐标和模型覆盖度）和 `regions/*.fa`（按坐标切好的 18S、ITS1、5.8S、ITS2、28S、12S、16S）。
- 不同模型的重叠命中互相竞争（线粒体 16S 也能对上核 28S 模型），取得分高者。
- `--models` 可换成自己的 HMM（例如按环节动物数据自建）；是否比 Rfam/barrnap 更准，需用留出数据验证，尚未做。
